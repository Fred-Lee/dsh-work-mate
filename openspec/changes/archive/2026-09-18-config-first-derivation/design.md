## 背景(Context)

用户观察到"扫描 @FeignClient 太消耗 token"。事实核查:出站扫描是纯本地文件扫描(`node:fs`),
无 LLM、无 token;真实仓库(2423 + 863 文件)完整推导实测 ~0.3s。因此本变更不宣称省 token,
其真实价值是:**配置即事实源、证据更稳、更快更可预测**。

已核实的技术前提:现有推导的名称档候选本就大量来自配置线索——`configClue` 对
`project.feign-client-config.internal-base.url` 这类键(命中 `*.url` 尾规则)即产出目标
`internal-base` 的名称档候选。也就是说,**只读配置文件即可覆盖该仓库全部 7 个 Feign 目标**,
Java 扫描的增量贡献主要是:路径档候选(端点明细)与"配置外"的调用(如硬编码 URL)。

真实数据(实测):该仓库可遍历 281 个文件中仅 21 个为 YAML;完整扫描 151 条线索中 137 条来自
Java、14 条来自配置——但**去重归并后的名称档候选,配置已全覆盖**。

关联约束:`detect-declaration-drift` 车道正在同一仓库实现中(在途 agent),其 `checkDeclarationDrift`
消费 `deriveDependencies`。本变更的实现必须等该车道落地后进行(文件所有权冲突),且其默认核对范围
与措辞需随本变更调整——已在本变更 Impact 中登记。

## 目标 / 非目标(Goals / Non-Goals)

**目标:**
- `config` 成为推导与漂移核对的默认范围:快、稳、来源单一。
- `full` 保留为显式深扫(要端点明细时用)。
- 结果对范围与来源可辨识;"无证据不产出候选"与人工确认路径不变。

**非目标:**
- 不提高代码扫描的召回率(动态 URL 识别是另一条线)。
- 不改变候选形状、确认落库、漂移三组判定的既有语义(只调整默认范围与措辞)。
- 不做配置文件变更监听/自动重扫。

## 决策(Decisions)

### D1. scope 选项挂在扫描与推导两层,默认 `config`
`scanOutboundCalls(rootPath, { scope })`:`config` 时 walk 只把配置扩展名的文件计入
(其余文件只做目录遍历跳过,不读内容);`deriveDependencies` 透传 scope 并在结果上标注。
- **理由**:单一开关贯穿"读什么"与"推出什么";默认快扫符合"配置是事实源"的用法。
- **替代**:拆成两个函数(两套上限/containment 逻辑易漂移);或 UI 层截断(服务面默认仍是深扫,
  语义混乱)。均否决。

### D2. config 范围的产物 = 仅名称档候选
配置线索天然给出"谁调谁"(服务级),给不出端点明细;明确接受这一损失,并在 UI 说明
"需要端点明细请用深度扫描"。
- **理由**:本仓用法以服务级边为主;名称档证据最稳。硬要从配置猜端点只会制造假明细。

### D3. 漂移核对默认随 scope=config,措辞如实降级
`checkDeclarationDrift` 默认 config;`staleDeclared` 的说明改为"未在扫描范围内找到证据"
(快扫时指明是配置范围),保留"需人工确认"引导。
- **理由**:漂移的"现实侧"来源必须与核对范围一致,否则措辞会夸大结论的强度。真要更强的陈旧判定,
  用显式深扫。

### D4. 深扫入口显式且标注代价
UI 上「深度扫描(含代码)」为勾选项,说明"更慢、可产出端点明细"。
- **理由**:深扫不是替代品而是补充;让增益与代价都可见,人自行选择。

## 风险 / 取舍(Risks / Trade-offs)

- [配置与代码不一致时快扫漏检(配置外硬编码调用)] → 深扫仍可用;漂移措辞已如实降级;人工确认路径兜底。
- [默认行为变化让既有用户意外] → 结果标注 scope;深扫一键可达;文档写明取舍。
- [config-only 让"配置了但从未调用"也成候选] → 可接受:配置的意图即依赖声明,误报率远低于
  代码启发式;且服务级边本就不区分使用强度。

## 迁移计划(Migration Plan)

实现排在 `detect-declaration-drift` 落地之后(文件所有权冲突)。纯增量:scope 为可选参数,默认值
变更不破坏既有调用(显式传 `full` 可复现旧行为)。回滚 = 恢复默认为 `full`。

## 开放问题(Open Questions)

- 漂移核对是否需要在 UI 上同时给出"快扫/深扫"两种结果?倾向:默认快扫,深扫按钮就在旁边,不做双列。
- 服务面 `deriveDependencies(group, opts?)` 的 group 级入口是否也要暴露 scope?倾向:透传即可,默认同全局。
