# WorkMate 工作台 UI 实测评估（2026-10-19）

测试环境：真实 profile（127.0.0.1:3080），Playwright + headless Chrome 1440×1000 / 900×900；
数据来自真实提案与真实团队 Run。截图在 `docs/assets/ui/`。

## 测试覆盖

| 场景 | 结果 |
| --- | --- |
| 列表视图 | 可加载；筛选/搜索/已归档折叠正常 |
| 看板视图 | 五段流水线正常，但版面利用率低 |
| 团队视图 | Run 列表正常；详情工件面板有数据源 bug |
| 控制台 | 指标与表正常，但表格单位/格式不一致 |
| 知识图谱 | 可渲染，但可读性差 |

| Console | 1 个 404（favicon），无 JS 异常 |

## P0

1. **团队 Run 详情把 TEST.md/TEAM-REVIEW.md 显示为“缺失”**
   - 证据：`team-final-run-detail.png`；API `/api/team/runs/:id/artifacts` 只读主检出，但工件在 target worktree。
   - 已修（`5c69ec0` 回退读 worktree），但当前 host 仍是旧模块，重启后生效。
   - 影响：用户会误判团队 Run 没产出审查/测试证据。

2. **知识图谱可读性差**
   - 证据：`audit-graph.png`：提案名被截断；同一行几十个“涉及”文字叠在连线旁；第三列“Git 提交”全空；归档/放弃提案全量入图。
   - 建议：默认只展示活跃提案；去掉逐边文字用 tooltip/图例；提案→项目两列 + 聚合边；加缩放/搜索/空态。

## P1

3. **团队视图空态浪费**：未选 Run 时右侧/下方大片空白，Run 状态居中列显得松散。建议自动选中最近 Run，或改成左列表+右详情的常驻两栏。
4. **控制台单位不一致**：卡片是 `5.8h`，表格却是 `552441.00` / `139820095.38` / `116468415.62`，σ 无单位；`conflict-a/b/c` 这类临时提案以 archived 出现在流程表。建议表格复用时长格式化，排除 abandoned，增加项目列。
5. **看板/列表版面利用率**：1440×1000 下看板列只有卡片高度，下方近 600px 空白；列表行信息密度低。建议列 `min-height` 撑满、空列给下一步提示；列表增加分支/目标数等列。
6. **创建模态步骤感弱**：只有标题 `步骤 1/3`，没有进度条/步骤名；旧流程“单项目根”和兼容字段占据首屏；基线分支要到第二步才看到。建议顶部三步 stepper、把兼容字段收进“高级”。
7. **项目树行拥挤**：`工作tree 0 / 脏 8 / 中 4` 在 1440 下换行错位，路径与分支互相挤压。建议固定列宽 + 省略号 + tooltip，窄屏改成下拉。
8. **控件风格混用**：自定义 `.wm-btn` 与 ui-primitives `Button` 并存，圆角/高度/焦点态不一致；列表的状态 Tag 与看板状态条风格也不同。建议统一到共享原子控件。

## P2

9. 团队工件用 `<pre>` 原样渲染 Markdown；可用共享 Markdown 组件。
10. “已隐藏 N 条已归档”用 DisclosureRow，但点击实际是筛选动作，语义不符。
11. 团队/控制台缺少加载 skeleton，只有“加载中…”。
12. `/workmate/favicon.ico` 404 造成控制台噪声。

## 建议落地顺序

1. 重启后验证团队工件回退（P0-1）；
2. 重做知识图谱为活跃提案视图（P0-2）；
3. 团队视图两栏 + 自动选中（P1-3）；
4. 控制台格式化/过滤（P1-4）；
5. 看板/列表密度与创建 stepper（P1-5/6）；
6. 项目树列宽与控件统一（P1-7/8）。
