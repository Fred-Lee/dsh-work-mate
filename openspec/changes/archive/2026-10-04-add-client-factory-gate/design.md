# Design — Add Client Factory Gate

## D1 为什么在 VM 里求值，而不是静态检查

静态检查只能看字符串（"bundle 里有 `__ModuleLoader__.load`"），而装载契约的失败模式是
**求值期**的：id 拼错、factory 不是函数、apply 没导出、引用了未声明的 external。
求值一次是唯一能同时覆盖这四点的低成本手段，且不需要 DOM 实现——用递归 Proxy 桩把
`document` / `window` / 未知全局都兜住，模块求值就会走完自己的顶层代码。

## D2 external 默认拒绝，而不是白名单提示

`require` 桩对白名单之外的名字**直接抛错**（并把名字记进 `deniedRequires`），这样
"新增了一个宿主依赖但忘了审核"必然红。白名单是门禁脚本里的常量，收紧时改一处。

## D3 边界要写在门禁自己的输出里

文件头与失败输出都写明：这是**工厂求值门禁**，不是端到端验收。`apply` 被调用与否、
被调用的返回值都不测——真渲染仍在真机。参考实现也如实这么标注，避免团队把"门禁绿"
误当成"UI 没问题"。

## D4 超时是两级

`vm` 的 `timeout` 选项管住同步死循环；门禁整体再设一层墙钟预算。踩坑常见于
`while(true)` 式的顶层初始化，两级都能兜。
