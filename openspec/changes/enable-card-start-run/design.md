## 背景(Context)

看板第 ③ 列"开发实施"只能读 run(已有 api/item/:id/runs 与 api/run/:taskId/events 路由),卡片从来
无法"起一个 run"。用户拍板四条:① 预填卡片标题+摘要;② agent 按场景智能选(默认 claude 拆解/
codex 并行/简单挑最快)且可改;③ 暴露级联开关,其余不露;④ 取消/重试/审批/合并留在执行看板,
看板只加"发起"入口,**不复制整套操作台**。

接入点已存在:`OrchestratorService.runParallelTask({prompt, agents, projectGroupId, cascade, timeoutSec})`
是 change A/C 的既有工具;`OrchestratorService.checkAgents()` 返回 `{claude?, codex?, …}` 可直接拿来
判断"已装"。
`WIP` 的边界:只拦"进第 ③ 列",**不拦列内再发起**——避免日常迭代被自己设的瓶颈堵死,
spec 已锁定。
持久化:起跑后 run 走 change A 的持久化时间线 + 游标续传;卡片 `runs[]` 已是 change A 写入的,
看板消费即可。

## 目标 / 非目标(Goals / Non-Goals)

**目标:**
- 看板从"观察窗"补"发起入口";运行生命周期管理仍由执行看板承担。
- 智能推荐降低日常选择负担;用户随时可改。
- 复用既有 orchestrator 工具与 SSE,不动宿主协议。
- 零新运行时依赖、零新基础设施。

**非目标:**
- 不在看板内做取消/重试/审批/合并(单一职责,操作放执行看板)。
- 不改 WIP 规则、不改冲突域默认、不改依赖图与忽略清单。
- 不做 agent 配额/费用管理(执行看板已有 orchestrator 工具,可后续)。
- 不做"卡片内起 run 与执行看板起 run" 的双路径差异——是同一条工具。

## 决策(Decisions)

### D1. 入口仅在卡片具备 projectGroup + 至少一个已装 agent 时出现
否则只显示「请先在执行看板发起」引导——避免"按钮在但提交就报错"。

### D2. agent 选择仅在三选项内(三档:`auto`/`claude`/`codex`)
- auto 档走"按场景":卡片描述含拆解/计划要素 → claude;含并行要素 → codex;其他简单任务
  → `checkAgents()` 返回的"已装"中速度最快者(本地以"已安装"集合中先 claude 后 codex 的回退顺序
  作为可实现的近似)。
- 简单文本特征即可(子任务/拆分/计划/并行等关键词 + 卡片描述长度 + agents 列表)——不引入 LLM 判断,
  保持 0 token / 0 网络。
- 用户可手动改:选了 `claude`/`codex` 后系统不再回退;改了即生效。

### D3. 预填"卡片标题 + 卡片 summary" + 默认勾选 cascade
最小化输入,默认带拓扑上下文(对 A/C/D 已有能力复用);超时秒数、agent 重新选择等参数不暴露
(超简 + 可在执行看板调),避免一张新表单的全套参数。

### D4. 卡片"原地不动" = 看板只加发起,运行生命周期仍由执行看板承担
点击「▶ 发起执行」直接调既有 `runParallelTask`;run 落地后,卡片 `runs[]` 由 change A 写入,
SSE 推回 → 卡片内 run 面板实时滚动。**取消/重试/审批/合并**继续在 `/helmsman-dashboard/` 上做,
看板在卡片里提供"去执行看板"链接。

### D5. WIP 仍只拦"进第 ③ 列",不拦"列内追加 run"
符合既有 spec(2024-08 已锁定);用户已在第 ③ 列内迭代不应被自己设的瓶颈堵死。

## 风险 / 取舍(Risks / Trade-offs)

- [agent 速度的"最快"判定是粗略] → 文档明确是"近似",用户可一键改;不读 LLM、不连服务。
- [看板无取消 = 多点跳] → 用"去执行看板"链接显式引导,不遮蔽问题。
- [cascade 总是默认勾上可能让 prompt 变长] → 与 change C 的级联注入语义一致;若 prompt 变长导致
  超时,可走"高级"折叠(后续);当前默认行为符合 A/C 的级联价值。
- [并发发起同一卡片多次] → 与既有卡片行为一致(每次新增 run,不冲突);用户自管。

## 迁移计划(Migration Plan)

纯增量:仅在 `packages/ui-board` 加 1 个新组件 + 1 个 API 代理调用,不改 orchestrator、拓扑、声明。
回滚 = 移除该组件(零数据副作用,卡片 `runs[]` 仍由执行看板的发起来填)。
