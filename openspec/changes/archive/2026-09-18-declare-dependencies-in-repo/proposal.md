## Why

目前依赖关系只能进 Helmsman 之后才知道:靠 ③ 扫描代码推导(启发式,需要人工确认),或手工在看板上录。
用户的实际诉求是**把索引前移到项目里**——每个仓库提前声明自己的对外依赖,Helmsman 在添加/抓取项目时
直接读取分析,人只需要**核对**,不必再另行录入与维护。

这个方向比"往 AGENTS.md 里写散文"更稳,因为它天然解决了三个问题:

- **没有副本与视角矛盾**:每个仓库**只声明自己的出站依赖**,每条边只有一个家(调用方);反向关系
  (谁调用我)由工具推导——这正是现有模型的样子(`restDependencies` 按 `from` 挂边)。手写散文则会在
  A 里写"我调用 B"、在 B 里写"谁调用我",两处迟早不一致。
- **随代码走、进 PR 评审**:声明与代码同仓库、同 diff、同审查,clone 下来即在;不经过 Helmsman 的 agent
  (直接跑 claude/codex 或 IDE agent)也能读到。
- **可验证**:仓库里的声明是机器可读的,可以对着代码双向核对(下一变更做),而散文无法校验。

管道**大部分已存在**,这让成本远低于新建子系统:导入流程已有 `ImportPreview`
(`dependencies: [{from,to,method,endpoints}]` + `source`)与"预览 → 人工勾选 → `importApply`(合并 + 成对去重)"
链路,`importApply` 内部就是"读现有拓扑 → 合并 → 去重 → 存盘"。本变更 = 新增一个导入源 + 文件格式 +
一处模型缺口(边的来源标记)+ 回写能力。

**已知的模型缺口**:`RestDependencyEdge` 目前**没有来源字段**,无法区分"仓库声明的边"与"推导后人工确认的边"。
不补这个,每次重新抓取都会把推导确认的边一起冲掉。

## What Changes

- **新增仓库内声明文件**`.helmsman/dependencies.yml`(v1):含本服务标识 `service` 与出站依赖列表
  `dependencies[]`(每项 `to` + 可选 `method`/`endpoints`/`critical`)。只声明出站,不声明入站。
- **新增导入源 `helmsman-declaration`**:文件解析为既有 `ImportPreview` 形状,复用现有"预览 → 人工核对 →
  应用"链路;应用走 `importApply` 的合并与成对去重语义。
- **边新增来源标记**:`RestDependencyEdge.source?: 'declared' | 'derived'`(缺省视为 `declared`,兼容存量)。
- **重新抓取的调和语义**:声明边**以文件为准**(新增缺失、移除陈旧——仅限 `declared` 边);`derived` 边
  **不受影响**。因此重复抓取是幂等的,且不会吞掉此前确认过的推导结果。
- **未登记目标可随抓取登记**:文件引用的服务若未在项目群中登记,抓取时提供"登记并确认",避免应用后
  立刻产生悬空引用。
- **回写能力(让"不用手写"成立)**:提供"把当前依赖写回声明文件"的动作——由工具草拟文件内容,
  人核对后提交。声明文件因此可以是**生成物**而非手写物。
- **文件缺失/损坏非致命且不静默**:仓库无该文件 → 明确提示"该项目未声明依赖"(而非报错);
  解析失败 → 报错并列出问题,绝不部分应用。

## Capabilities

### New Capabilities
- `dependency-declaration`:仓库内依赖声明文件的格式与语义(仅出站、服务标识、服务级与带明细两种边)、作为导入源的抓取与人工核对流程、边的来源标记与重新抓取的调和规则、未登记目标的登记路径,以及把当前依赖回写为声明文件的能力。

## Impact

- `packages/memory-topology`:`types.ts`(边新增可选 `source`、归一化保留、合并去重时的来源语义)、
  新增声明文件解析/序列化模块、`index.ts`(抓取与回写入口、未登记目标的登记路径)、单测。
- `packages/ui-dashboard`:项目群配置新增「📥 从仓库抓取依赖」与「💾 写回声明文件」入口
  (`client/App.tsx`、`client/api.ts`、`api.ts` 路由),抓取复用现有导入预览对话框。
- 文档:`docs/USAGE.md`(声明文件格式、抓取与回写流程、核对要点)、`docs/ARCHITECTURE.md`(声明作为
  导入源、来源标记与调和规则)、`docs/VERIFICATION-GUIDE.md`(在一个临时仓库上放声明文件 → 抓取 → 核对)。
- 后续(独立变更):声明与代码的**漂移核对**——"声明了但代码里扫不到""代码里扫到但没声明"作为体检项。
