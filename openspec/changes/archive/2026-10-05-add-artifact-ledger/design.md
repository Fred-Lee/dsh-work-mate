# Design — Add Artifact Ledger

## D1 声明从既有注释读，不新增格式

`<!-- writes: ... -->` 已在 swarm 阶段用于装批；`design.md` 用同构的
`<!-- files: ... -->`（语义：本设计预计触碰的文件）。两处都缺 → `declared` 为空，
漂移计算**不报 undeclared**（没有声明就没有"未声明"这个说法），工具会明确说明
"未声明范围，无法判定漂移"——不制造假阳性。

## D2 实际集合只看本提案的标记提交

`git diff --name-only <oldest>^..<newest>`（`oldest`/`newest` 来自
`[proposal:<id>]` 标记提交）。用整个分支的 diff 会把别人的改动算进来；用单个提交看不到
全貌。标记提交是本提案与代码之间**唯一**的正式边，界就画在这里。

## D2 补：变更目录本身不算交付物

实际集合会剔除 `<openspecRoot>/changes/**`（提案自己的 spec 目录）：那是**计划本身**，
不是交付物。否则每个提案都会把自己声明成"未声明改动"，漂移立刻变成噪声。

## D3 哈希是账本的核心，不是装饰

账本每条记 `sha256` + 字节数 + 覆盖它的提交。这让"审查的是哪一版工件"可验证
（与 review 分级里"审查者头 + 影子"呼应）：归档目录里的 `review.md` 哈希与审批记录一起，
任何被追责的问题都能定位到具体内容。

## D4 漂移门默认关闭

`writes` 声明是这次才引入的约定；一上来默认拦截会让所有历史提案无法归档（它们没有声明）。
默认 `planDriftGate: false`：**记录、展示、不拦**；采纳声明习惯后由用户显式打开。
