# Design — Add Decision Cache

## D1 缓存的是"同题同参"，不是"同一个提案"

键严格包含 `node + state + question + options + provider + model + samples`。state 变了
（新决策、新 diff、新发现文本）就是不同的题，必须重新判断——**绝不能按提案 id 缓存**，
那会把"上次的判断"当成"这次的事实"。

## D2 只缓存模型答案

`rules` 是确定性函数：命中缓存与直接计算的结果逐字相同，缓存只增加 I/O。所以只缓存
`agent`（以及将来的 `jev`）的回答。

## D3 fail-open 是硬要求

缓存文件损坏、权限不足、写到一半崩溃——都不允许影响判断：读失败当作空缓存继续调用 provider，
写失败只记警告。**缓存是性能层，不是正确性层**，这条边界不能含糊。

## D4 上限 + 淘汰

`decisionCacheMax`（默认 500）按 `at` 保留最新的若干条，避免无限增长；
淘汰在写入时顺带完成，不做后台任务。

## D5 命中要看得见

`cached: true` 写进 outcome 与 `decision` 事件。否则"这次判断很快"会被误读成"模型很快"，
而真相可能是复用——对成本核算尤其重要。
